== Finding (fixed in this commit) — both directions of the same overclaim

ADR 0018 rule 3 said "the environment beats .env" under the heading "Resolution rule,
every layer". On this branch that is implemented on exactly TWO layers — internal/config
(Go) and tools/ch, which capture the environment before sourcing .env. The five other
shell tools (build-model.sh, apply-sql.sh, load.sh, reconcile.sh, truncation-test.sh)
still run a bare `set -a && . ./.env && set +a` (verified by grep: build-model.sh:18,
apply-sql.sh:17, load.sh:13, reconcile.sh:18, truncation-test.sh:24), so for them .env
wins.

Meanwhile docs/RUNBOOK_UNSEEN.md §A5 claimed the opposite overreach: "EVERY tool does
[set -a && . ./.env]" — no longer true for tools/ch and the Go binary after fb1f98a.

Both docs now state the split exactly:
- ADR 0018 rule 3 names the two layers where the environment wins and the five scripts
  where it does not, and cross-references RUNBOOK §A5.
- RUNBOOK §A5 says "most tools" and names the two ADR-0018 exceptions.

Left UNCHANGED, deliberately: docs/SESSION-2026-08-01.md (historical record) and
docs/EXPLAINER.md's bug-13 row "CH_DATABASE silently ignored — open" — still accurate,
because the load path (load.sh, build-model.sh) genuinely still ignores the environment.
Extending the env-capture to those five scripts is open work (same family as Q33).
