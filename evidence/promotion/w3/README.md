## Why this is a refusal, not a caveat

**D1 · The feature's own proof harness cannot run.** `tools/publish-test.sh` calls
`tools/apply-sql.sh --database` at lines 250, 253, 709 and 911. `main`'s `apply-sql.sh` has no
option parser — every argument is treated as a filename:

```
$ TARGET=local tools/apply-sql.sh --database sonyliv_pub sql/12_publish.sql
applying to LOCAL: docker exec ch
no such file: --database
exit=1
```

That flag lands in **wave 1** (`6355048`). So the convergence claim a judge will test — *all four
tiers equal a from-scratch rebuild across bootstrap, growth, shrink, dimension change, a 46-minute
straggler and 200 forced republications* — **cannot be re-derived from the promoted tree.** That is
check 3, and it is precisely the "a feature whose claimed number cannot be reproduced does not
promote" clause.

**D2 · The only remaining route to a scratch database resolves to `sonyliv`.** `main`'s
`apply-sql.sh` line 17 sources `.env` *after* reading the caller's environment:

```
$ ( export CH_DATABASE=scratch_probe; set -a; . ./.env; set +a; echo "$CH_DATABASE" )
sonyliv
```

So `CH_DATABASE=<scratch> tools/apply-sql.sh sql/12_publish.sql` installs the publisher schema into
the **graded database**, silently. The `--database` flag is absent and the env route is captured.
Wave 1's `f2499ea` and `06a720d` are what add the precedence rules *and* the graded-database write
guards. Promoting a publisher onto a tree with neither is the same database-resolution family
(**Q33**) as the incident this gate exists because of.

**D3 · `make model` is broken.** ADR 0016's `build-model.sh` is a 6-stage script whose stage 6/6
applies `sql/15_normalise.sql` — **ADR 0011, wave 2, not on `main`**:

```
  MISSING sql/15_normalise.sql   <-- build-model.sh applies it (line 107)
```

Hand-editing it out would ship a `build-model.sh` that is neither `main`'s nor `dev`'s — an
unreviewed hybrid on the critical path, with no write guards. That is not a promotion.

**These are not three separable annoyances.** They are the same fact: ADR 0016 extends a rebuild
script and a test harness that waves 1 and 2 had already moved. `PROMOTION.md` says so itself —
*"Wave 2 is now on the critical path… Promote wave 2 next, and do not let other waves overtake
it."* W3 overtaking W1 and W2 is what produced all three.

## What DOES hold — verified, not assumed (the W2 lesson)

Every claim below was checked by grepping the **promoted tree**, not by reading the ADR.

**`mv_user_minute` is genuinely retired.** No `CREATE MATERIALIZED VIEW` for it survives anywhere.
The three remaining references are two `DROP VIEW IF EXISTS` (`sql/45_user_concurrency.sql:55`,
`tools/build-model.sh:76`) and one comment. ✓

**`cc_user_minute` is `ReplacingMergeTree(computed_at)`.** `sql/45_user_concurrency.sql:82`. The
two `AggregatingMergeTree` hits in that file are prose in the WHY comment, not DDL. ✓

**`tools/publish-test.sh` contains no unqualified SQL.** All 20 write statements are qualified with
`${LIVE}.`, `${CTL}.` or `${db}.`; `LIVE`/`CTL` are pinned scratch names and `PROD=sonyliv` is
marked read-only. The statements that *are* unqualified by design — those cut from `sql/45` and
`sql/50` between `PUBLISH_EXTRACT` markers — execute over HTTP with an explicit `?database=` URL
parameter, so they cannot resolve against the connection's default database. ✓

## Check 4 — both measurements

**4a · the graded database passes `dev`'s gate.** Run from a throwaway worktree at `origin/dev`
(`3ed7f05`), so it is unambiguously *dev's* gate, verified write-free first:

```
minutes_compared=17028 | mismatched=0 | max_abs_diff=0 | peak=2917 | PASS
```

**4b · this branch's own gate, and the difference accounted for.**

```
minutes_compared=17028 | mismatched=177 | max_abs_diff=39 | peak=2887 | MISMATCH
```

**Attributed independently, not taken on trust.** `main`'s gate differs from `dev`'s in *three*
places, not two: the two `arrayFirst(x -> x > p, p2.rs)` resume predicates **and** a
zero-length-window `arrayFilter(w -> w.2 > w.1, …)`. Patching **only the two `>` → `>=`**, leaving
the `arrayFilter` alone, moves the branch gate to:

```
minutes_compared=17028 | mismatched=0 | max_abs_diff=0 | peak=2917 | PASS
```

So all 177 mismatches are attributable to `0c0f020` (ADR 0009's same-second resume fix, wave 2),
and the `arrayFilter` accounts for **none** of them — a slightly stronger result than the W1 check-5
verdict recorded. `sql/90_reconcile.sql` was restored immediately afterwards; the patch was never
committed.

## Check 6 — the docs failure this promotion would introduce

`grep -rn '3\.4 s' --include='*.md'` on the promoted tree finds the retired straggler figure as a
**current** claim in three places:

- `TODOS.md:23` — *"corrected in **3.4 s** reading 11.6% of `ev_raw`"*
- `docs/ARCHITECTURE.md:90` — *"1 session in **3.4 s**"*
- `docs/ARCHITECTURE.md:111` — *"**measured 3.4 s and 11.6% of `ev_raw`**"*

`dev` fixed exactly those in `5baeaa9`, which was **not** cherry-picked: its replacement wording
cites ADR 0020 (*delta correction flat ~0.3 s; tier maintenance 0.25 s at 1×, 7.3 s at 100×*), and
ADR 0020 arrives in **wave 4** — its commit `535ea96` modifies a `tools/scale-test.sh` that does not
exist on `main`. Importing the numbers without the ADR that owns them, or the ADR without the
evidence that proves it, are both worse than saying so here.

`docs/adr/0006:22` and `docs/adr/0013:12,113,114` keep the 3.4 s figure **deliberately** — they are
dated records, and `5baeaa9`'s own message says ADR 0020 supersedes rather than rewrites them.
Those are correct as they stand.

**ADR 0023** (publish-visibility contract, −87.8% for up to 13.6 s) is **not in this tree**, so
there is no claim of it here to match against code.

## The unblock

In order, each through its own six checks:

1. **Wave 1** — ADR 0018 target resolution, `tools/ch` `TARGET`, `apply-sql.sh --database`, and the
   graded-database write guards (`6355048`, `f2499ea`, `06a720d`). Fixes D1 and D2.
2. **Wave 2** — ADR 0009 / 0011 / 0014, **including `df6e7a2`**, the follow-up W2 missed. Fixes D3,
   and collapses check 4b's 177 to 0.
3. **Then re-run this branch.** Checks 1, 2 and 6 should clear; check 3 becomes runnable and the
   convergence claim can finally be re-derived; and `5baeaa9` can be picked verbatim once ADR 0020
   lands in wave 4 — or the ARCHITECTURE/TODOS wording adapted at wave 3 with the figure named as
   forthcoming.

Nothing here was written to `sonyliv`. `REBUILD_GRADED` and `APPLY_GRADED_DESTRUCTIVE` were never
set; `publish.sh`, `build-model.sh` and `publish-test.sh` were never run against any target.
