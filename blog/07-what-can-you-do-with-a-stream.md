# What Can You Do with a Stream?

## Processing pipelines, complex events, analytics, materialized views, and search

## Processing Stream

The question in focus in this section is what you can do with a stream once you have it?

1. You can send to other storage systems, like databases, search indexes, caches, it is one of the way to keep your database in sync, if the database is the only client consuming from the stream.

2. If a human is the ultimate consumer of the stream then you can notify the users by an email, a push notification or any alerting mechanism

3. You can construct a processing pipeline to generate one or more output stream (derived streams) from one or more input stream. The piece of code that does the processing is usually know as an operator or a job. The consumption is done in read only fashion and the output is written in an append only fashion.

## Uses of Stream Processing

Stream processing finds it major use in monitoring purposes, in fraud system to generate alerts is the credit card activity is suspicious. To alert if a machine is faulty in a warehouse or a factory. In trading systems, to examine price changes and execute a change accordingly.

These kind of applications requires sophisticated pattern-matching and correlations.

## Complex Event Processing (CEP)

Just like regular expressions helps you to get a particular section of string based on pattern similarly CEP helps to search for a certain pattern of events in a stream. It is an approach developed to analyze event streams.

The patterns are described in a declarative Query Language like SQL or any graphical interface. An internal state machine is maintained in the processing engine, which receives the input streams, and when a pattern match is found then a complex event containing the details of the event that was matched is generated by the engine and given to the user.

CEP works in on an opposite mechanism then databases, for CEP the set of queries are stored and the stream of events are transient in nature, where as in databases it is the data which is stored.

## Stream Analytics

Another area where stream processing is used is stream analytics, even though there is a thin line of different between stream analytics and CEP, in stream analytics rather than finding out a certain sequence of event from event stream, certain aggregation or statistical metrics are detected such as measuring the rate of some type of event, calculating the rolling average of a value over a period of time, comparing current statistics with previous one to generate alerts.

These metrics are generally taken over a fixed period of time, the time period that you select is usually called a window. The values are majorly averaged out to avoid fluctuations and give a general trend over the window.

Mostly stream analytics tools used mathematical algorithms like bloom filters and probabilistic algorithms to analyze events. With probabilistic algorithms the memory can be efficiently optimized with approximations over the input events. Flink is an open source stream processing tool designed with analytics in mind.

## Maintaining Materialized Views

We have already discussed in previous blogs that how streams can be used to keep an application's multiple storage (cache, search indexes) systems in sync with the databases changes.

A materialized view is an alternative view onto some dataset, hence this needs to be maintained with all the data changes. In event sourcing, an application state is also a materialized view that can be derived from the event log, but the application state needs to take care the events happening since the beginning so over here the start time of the window needs to be the start time of the application, since the data could be huge, approximation techniques could be used like log compaction, Kafka streams is one example.

## Search on Streams

Besides CEP, sometimes a complex search criteria like a full based text search can be a need of an application, For example the users of a real estate website should be notified if a property matching their requirements is available on the website.

Conventional search engines first index the documents and the queries over the index, but over here queries are indexed and documents run past the queries. As the data grow large, documents along with queries can be indexed to optimize performance.

## Message Parsing and RPC

Even though there is quite a difference between message parsing systems and stream processors, for example communication in message passing systems being mostly one to one and ephemeral whereas it is durable and multi-consumer in case of stream processing, actors in message passing systems can communicate in arbitrary ways whereas in the latter, usually acyclic pipelines is setup for the derivation of output stream from the input streams.

With invention of distributed RPCS, like Apache Storm, a lot of cross overs between these two systems have been observed, in which queries are interleaved with events from input streams , and results can be aggregated and sent back to the user.
