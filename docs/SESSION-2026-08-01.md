## 3. The measurements that drove the design

Every number below was run, not reasoned about.

| Question | Answer |
|---|---|
| Do heartbeats stop while backgrounded? | **Yes** — 0.047/min vs 4.72/min active, a 100× drop |
| Do heartbeats survive a pause? | **Yes** — 0.756/min, ~1 event/79 s, *inside* any sane gap threshold |
| Is `VideoHeartbeat` a 60-second beat? | **No** — bursty telemetry, inter-arrival p50 **0 s**, p90 40 s, p99 49 s |
| How late do stragglers arrive? | 2.2% of sessions, up to **2,081 s** after `VideoSessionEnd` → W = 2,400 s |
| Cost of the unclosed-pause rule | conservative 1,949.3 h vs permissive 2,048.6 h — **+99.3 h, 5.09%** |
| Does adding dimensions blow up the delta table? | **No** — hard ceiling of 36,930 rows regardless of dimension count |
| Are the 4,210 duplicate rows harmful? | **No** — provably inert; identical intervals, 0 of 3,725 minutes differ |
| Serving layer vs interval expansion | 299 KB / 23 ms vs 2.55 MB / 56 ms — **8.5×** |

**The single most consequential finding:** gaps detect backgrounding but **not** pause. A gap-only
model counts paused time as watching, which the statement forbids. That is why the model is a hybrid
and why `sql/30_build_intervals.sql` subtracts pause windows explicitly. See
[ADR 0007](adr/0007-gate-answers-pause-needs-explicit-handling.md).

## 4. Bugs found

Ordered by how badly each would have hurt on the graded day.

| # | Bug | How it would have shown up |
|---|---|---|
| 1 | **The gate silently passes on any day that isn't 2026-07-26.** Target minutes are literals; zero rows → `grep -q MISMATCH` finds none → "PASSED" | Green gate, unknown correctness, on the unseen day |
| 2 | **The gate never compares idle minutes.** Proven by fabricating 500 viewers at an idle minute — gate still PASSED | Invented viewers, invisible |
| 3 | **Absorption did not converge.** `ReplacingMergeTree(interval_end)` assumes re-derivation only *extends*; 316 intervals ran 60 s long, 315 stuck open | Peak overcounted by 37 (+1.3%) after any late arrival |
| 4 | **`any()` for dimensions was 44.5% wrong and non-deterministic.** The player emits a sentinel before resolving a track; different `max_threads` gave different hashes | 73.5% of sessions in the wrong audio bucket at the peak minute; two rebuilds serving different answers |
| 5 | **Delta counters wrapped.** `starts/ends` were `UInt64`; ADR 0006 negates a corrective row. `sum()` stayed right by modular arithmetic so it hid; `max()` returned 1.8e19 | Silent 22% inflation |
| 6 | **Same-minute double count.** A session pausing and resuming inside one minute emitted two `+1`s — 4,797 sessions, 44% | 556 of 1,903 minutes wrong, max error 195 |
| 7 | **Dictionary cannot serve a negative key.** Simple-key `HASHED` indexes on `UInt64`; `content_dim` has `-987654322`. Loads clean, throws on lookup | Hard query failure on the unseen day |
| 8 | **Re-loading the same CSV doubles the day.** The claimed idempotency setting is for non-replicated MergeTree; Cloud is SharedMergeTree | Every number doubled |
| 9 | **A `Map` outside the sort key silently relabels rows on merge** (26.7 rejects it; Cloud 26.2 accepts) | Wrong dimension attribution, only after a background merge |
| 10 | Tail grace applied after an explicit pause | 60 s of backgrounded time booked as watch time |
| 11 | `CH_DATABASE` in the environment silently ignored | A retarget that appears to work and writes to production |
| 12 | Bootstrap script: uninitialised counter under `set -u`, and readiness probing `/` (404) | Timeout against a server that was up |

**Bugs 1 and 2 are the important ones**, because they mean every "verified" claim in this session
rests on a gate that was weaker than advertised.

## 7. Process notes

**What worked.** Seven subagents on disjoint file/database ownership. Isolation was enforced by
giving destructive work its own database (`sonyliv_trunc`, `sonyliv_unseen`) — production was never
a write target for a test. Every agent was told to report measurements rather than conclusions, and
several came back with results that contradicted their brief, which is the point.

**Mistakes I made, recorded so they are not repeated.**
- `git add -A` while agents were writing swept in-progress files into unrelated commits. Explicit
  paths from then on.
- Appended to `.env` without a trailing newline and fused two variables. Caught from the resulting
  error, repaired.
- Wrote a gate whose failure check was `grep -q FAIL` — it matched the script's own header prose.
  The replacement `grep -qE "│ FAIL"` matched **nothing**, so a failing gate would have exited
  0. Fixed with an unambiguous `MISMATCH` token and **negative-tested** by corrupting data.
- Reported "the gate passes" as a general claim when it was dataset-specific.

**The rule that earned its keep:** every model change re-runs the gate, and the gate has been
negative-tested to prove it *can* fail. Bugs 3, 5 and 6 were all caught by a test rather than by
reading code.
