## 4. Critical unresolved findings

### 4.1 P0 — the incremental publisher does not keep every advertised aggregate correct

ADR 0013 updates `session_intervals` and `cc_minute_delta`. It does not rederive `cc_hour_agg` for
touched hours. Therefore `v_concurrency_hour*` and `v_concurrency_day*` can remain on the pre-arrival
answer while minute serving changes.

The user tier has a separate, deterministic problem. `mv_user_minute` fires when the finalizer inserts
new interval rows and merges `uniqExact` states by set union. It can add membership but cannot retract a
user from a minute or dimension bucket covered only by a superseded interval. The repository already
documents this asymmetry in `sql/45_user_concurrency.sql`, and `tools/build-model.sh` has to truncate
`cc_user_minute` on a full rebuild for exactly this reason. Incremental correction does not perform
that reset or an equivalent retractable-state operation.

Consequences:

- Session minute total can be current while user concurrency is inflated.
- Minute total can be current while hour/day peak and average remain stale.
- The upstream benchmark explicitly includes minute/hour/day and filters, so core-minute convergence
  is not sufficient to mark "continuously updated aggregates" done.
- `TODOS.md`, `WALKTHROUGH.md`, and `docs/ARCHITECTURE.md` currently overstate the completion scope.

This follows directly from the write paths and table algebra; the shipped publisher harness does not
instantiate or compare these tiers, so it cannot disprove the finding.

### 4.2 P0 — minute-boundary semantics are unresolved and internally self-confirming

The current expansion includes `toStartOfMinute(interval_end)` and the delta path closes at the next
minute. An interval ending exactly on a minute boundary is therefore counted in the minute beginning
at that boundary. Under standard half-open overlap semantics, it has zero overlap with that minute.

Measured impact on this dataset:

- 505 intervals across 493 sessions expose the boundary case.
- A half-open alternative changes 91 minutes and 302 viewer-minutes.
- Peak changes from 2,917 to 2,916.

Both `sql/90_reconcile.sql` and the serving SQL use the same inclusive convention, so a green gate
cannot choose between the two interpretations. Mentor question Q8 must be answered or judge
spot-check semantics can disagree while every local gate stays green.

### 4.3 P0 — publisher crash consistency has an unrecovered claim window

Code-inspection finding, not a reproduced production incident:

1. `publish.sh` writes `cc_publish_batch`.
2. It inserts the dirty timestamps into `cc_publish_consumed`.
3. Only then does it append the `claimed` phase to `cc_publish_runs`.

If the process or the third statement fails after step 2, the next process sees no in-flight run, but
the dirty markings are already excluded as consumed. The batch is orphaned and the update is skipped.
Phase markers and insert-deduplication tokens protect failures after `claimed`; they do not close this
earlier window.

The state transition needs an atomic identity/protocol or a recovery scan that recognizes consumed
markings with a batch but no claimed run.

### 4.4 P0 — concurrent finalizers can corrupt correction-by-diff

Code-inspection finding, not a reproduced production incident:

There is no lease, lock, or compare-and-set around "find in-flight run, then claim." Two publishers can
both observe no in-flight run and claim the same dirty sessions. Each can negate the same old
contribution and emit the new contribution. Starting from `X`, the combined result becomes
`X - X - X + X' + X' = 2X' - X`, not `X'`.

`run_id` is current epoch milliseconds and is also not guaranteed unique across simultaneous
processes. Until this is fixed or operationally enforced, ADR 0013 requires exactly one publisher
process, but that invariant is not encoded.

### 4.5 P0 — `marked_at` is not an insert identity

`cc_publish_consumed` is keyed only by `DateTime64(3) marked_at`, and the ADR says this identifies an
insert. Millisecond time does not guarantee uniqueness across independent inserts. Normally two rows
with the same timestamp are claimed together, but a slower insert that becomes visible after another
same-millisecond insert was consumed can be suppressed permanently. The five-second settle delay
reduces the probability; it does not establish uniqueness or atomic visibility across independent
inserts.

The proof used inserts separated by much more than one millisecond and does not test collision plus
slow commit.

The repository's current choice is `HEARTBEAT_GAP_S=150`, `TAIL_S=60`, with an unclosed pause remaining
paused. A sensitivity sweep produced:

### 4.7 P1 — deduplication is not inert at filter grain

The existing dedup artifact says dedup is inert because duplicates share the same session state. That
was true for the old headline grain. The current model carries seven dimensions, including subtitle
and audio language, so the old conclusion no longer covers the advertised filters.

A deterministic raw-versus-deduplicated rebuild measured:

- Same total intervals, total watch hours, and total peak.
- Six interval dimension attributions changed.
- Audio-language curves changed for `hin`, `non`, and `unk` across 18, 15, and 26 minutes.
- The `UNK` audio peak changed from 183 to 184.

Thus upstream step 3, "filtering and deduplicate late or repeated events," is not fully validated for
dimensioned answers even though the headline total is stable.

### 4.8 P1 — one tuple per merged viewer-minute is not multi-bucket occupancy

The current derivation chooses one dimension tuple for a merged run/minute. Direct interval expansion
can place activity into multiple dimension buckets when attributes change during a session. Comparing
the serving cells with direct expansion produced:

- 538,332 seven-dimension cells, 11,304 mismatches, maximum absolute difference 5.
- At the common platform/country/content grain, 427,143 cells, 157 mismatches, maximum 1.

The total curve remains additive and exact. Filtered truth requires an explicit product decision:
"attribute each active minute once" versus "count every bucket occupied during the minute." The docs
currently present the choice as settled without upstream confirmation.

### 4.9 P1 — production has no continuous publisher installed

Live `system.tables` inspection found `cc_user_minute`, `mv_user_minute`, `cc_hour_agg`, and the
hour/day/user serving views in `sonyliv`. It found none of `session_dirty`, `mv_session_dirty`,
`cc_publish_batch`, `cc_publish_consumed`, `cc_publish_runs`, or `v_cc_publish_lag` there.

Those publication objects exist only in scratch. ADR 0013 correctly states this; higher-level docs
that simply say publication is done are misleading. Even `tools/publish.sh --database sonyliv
--status` is blocked by the production write guard unless the write-override flag is supplied, despite
status being read-only.

### 4.10 P1 — the benchmark evidence package does not exist

The evidence directory contains reconcile, load guard, dedup, truncation, content, tie-break,
publisher, and rehearsal files. It does not contain a benchmark answer set, `evidence/benchmark/`, or
a query-log/trace bundle covering the required minute/hour/day and dimension-filter query matrix.

One fast ad hoc query is not enough to support dashboard-grade latency or submission requirements.
The final benchmark artifact must bind query text, parameters, answers, latency, rows/bytes read,
query IDs, target commit, and dataset checksum.

### 6.1 Local database selection

The Go configuration and several tools use `CH_DATABASE` for local operations rather than
`CH_DATABASE_LOCAL`. With the repository `.env`, `CH_DATABASE=sonyliv` points local verification at a
database that does not exist, producing an opaque HTTP 404. Overriding `CH_DATABASE=default` makes the
local verify path pass.

`tools/ch` also relies on the local server default database, while Go uses the exported Cloud database.
The same command therefore targets different database names depending on implementation.

### 6.2 Local schema parity

The local database had the stateless objects but empty interval/delta tables during inspection. Its
stateless aggregate uses `uniq` where the exact Cloud path uses `uniqExact`. Local green checks cannot
be treated as proof of Cloud query semantics until the schemas and data are synchronized.

## 8. Additional serving caveats

### 8.1 Content views are sparse change points

The content views enrich delta change points. At an arbitrary exact minute, summing current rows by
content/title/category can undercount because unchanged concurrency must be carried forward. They are
safe for the documented range-max flow that reconstructs the curve; they are not dense snapshot
tables. `video_type` happened to match the total at the measured peak, which does not remove the
general caveat.

### 8.2 Normalization is not deployed

`v_concurrency_minute_audio_norm` was absent from `sonyliv`. On an isolated current rebuild, raw Hindi
peak 1,774 normalized to 2,196, not the stale 1,791 to 2,213 pair in docs. Claims about normalized
production answers are therefore not current Cloud facts.

### 8.3 Publisher queue retention is an operational correctness bound

`session_dirty`, batch, and consumed state use seven-day TTLs. If publication is stopped or unable to
drain for more than seven days, work can expire. No alert or hard operational SLA currently enforces
"publisher lag must remain below retention."

## 10. Required closure before claiming full validation

1. Get explicit mentor/organiser answers for minute boundaries, unclosed pauses, heartbeat tail/gap,
   session versus user counting, and changing-dimension attribution.
2. Extend the publisher so user and hour/day outputs converge after growth, shrink, dimension change,
   and late stragglers; add those tiers to `publish-test.sh`.
3. Close the consumed-before-claimed crash window and enforce a single active publisher with a real
   lease/fencing token; test crash injection at every phase and two simultaneous publishers.
4. Replace millisecond timestamp identity with a collision-safe insert/change identity.
5. Decide whether to deploy ADR 0013 to `sonyliv`; if deployed, monitor publish lag versus seven-day
   retention and measure mutation/part growth over sustained runs.
6. Make dedup and dimension-attribution policy explicit, then reconcile every benchmark filter grain
   against an independently derived truth.
7. Fix the reconcile evidence parser and its fixture, repair ClickStack user sources, and capture a
   signed-in end-to-end dashboard result.
8. Produce the complete benchmark and unseen evidence bundles from pipeline queries and query logs.
9. Update the explainer, architecture, walkthrough, TODO, checkpoint handoff, and deck so every
   headline claim has one scope and one current number.
10. Pin the CI toolchain, fix remaining ShellCheck warnings, and add coverage for the critical parsers,
    publisher state machine, and target/database selection.

## 11. Final conclusion

No additional feature should be added merely to improve the story. The remaining work is closure of
correctness and evidence gaps already required by upstream.

What can be claimed now:

> The current batch-built session-concurrency curve is internally exact against an independent raw
> derivation on all 17,028 observed minutes under the repository's documented assumptions. The ADR
> 0013 finalizer is additionally proven to converge for intervals and the dimensioned minute-delta
> serving layer in isolated Cloud tests, including late and unchanged sessions.

What cannot yet be claimed:

> The implementation matches judge raw-event spot-checks, continuously maintains every minute/hour/day,
> user, and filtered aggregate, is safe under crashes or multiple publishers, is deployed on the
> graded database, or has complete benchmark/unseen/ClickStack evidence.
