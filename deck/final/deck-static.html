That one fact drove the design.

land first, type second

All-String, header-aware. A malformed row costs a row, not the file — and a column we have never seen survives instead of being dropped at the door.

quarantine, not deletion

Unusable rows go to a table with a reason. Three timestamps out of range. They are countable and inspectable — a judge can ask what we excluded and get an answer.

type-aware, not blanket cleanup

12 case-drifted Pause controls canonicalised. Identifiers, catalogue prose and raw filter values are not rewritten — normalisation happens at query time, so storage stays raw.

how we know it is right

The gate will not agree with itself.

0

mismatched minutes, out of 3,201,716 compared. Truth is recomputed from raw events, by a different implementation of the same spec — window functions against array splitting — so an error in one shows up instead of cancelling out. It never reads the serving tables.

fails on silence too

Zero rows compared is a failure, not a pass. A gate that cannot see its data must not succeed quietly.

11 test suites

Golden cohorts solved outside the pipeline, property tests against an independent interpreter, 32 sabotage-checked edge fixtures.

determinism, proven

26 of 27 queries byte-identical across two ClickHouse versions, two engine families, 3 vs 10 threads.

122 s · 3.57 GiB · spilled to disk

89,850,838 events. 1.09 million sessions. Query latency is unchanged because the delta phases are window-bound by design — hour-clipping means a query reads one hour, whatever the history behind it.

what breaks first — named, not guessed

Interval derivation memory. At 100× it failed at default settings; spill alone did not rescue it; spill + 2 threads did. Dictionary memory stayed flat at 17 MiB — it keys on the catalogue, not the audience.

optimisations in place

Hour-clipped deltas (flat reads) · promoted cubes per dimension subset · uniqExact state merge instead of re-scan · chunked backfill under the partition cap · dictionary join on the catalogue.

the honest limit

28 parts, 930 merges, slowest merge 36 s at 100×. Nothing wedged, but the build is where the next engineering goes — not the query path.

Cloud pins the limit read-only. Raising it returns Code 452 unconditionally — a second failure, not a fix. Solved by chunking: 64 + 38.

the half-built model

A build died mid-run. Re-running without truncate doubles an AggregatingMergeTree — and looks entirely plausible. A guard now refuses to serve a partial model. It fired for real.

a test that stopped testing

One template silently matched nothing, turning an incremental test into a full rebuild that converged by construction. Caught because its sabotage half went quiet.

Every one of these was caught by something refusing to pass, not by someone noticing.
